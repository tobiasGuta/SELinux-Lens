# Authorized audit access design

Status: proposal for [issue #3](https://github.com/tobiasGuta/SELinux-Lens/issues/3). The application currently queries auditd logs only with the desktop user's existing permissions. On Fedora Workstation 45 with SELinux enforcing, `ausearch` reported permission denial for an unprivileged desktop process whose user already belonged to `wheel`. That result covers one workstation and one account.

## Sources considered

| Source | Coverage and authorization | Decision |
| --- | --- | --- |
| auditd logs via `ausearch` | The Linux Audit CLI reads the configured log and understands multi-record audit events. The user's existing file access governs a direct query. Its output may contain unrelated records from matched events. [Linux Audit manual](https://github.com/linux-audit/audit-userspace/blob/master/docs/ausearch.8) | Keep the direct unprivileged query. Use this source first when evaluating a constrained reader. |
| systemd journal | journald can receive audit messages. Availability depends on the audit socket, collection, storage and the caller's existing visibility. A trusted `_TRANSPORT=audit` match identifies the transport and says nothing about missing records. The customary journal access groups grant visibility beyond AVC records. [journald](https://www.freedesktop.org/software/systemd/man/latest/systemd-journald.service.html) · [journalctl](https://www.freedesktop.org/software/systemd/man/latest/journalctl.html) · [Journal fields](https://www.freedesktop.org/software/systemd/man/latest/systemd.journal-fields.html) | Consider an explicitly identified source for already authorized readers after verifying coverage. An empty journal query cannot establish that the system had no AVC denials. |
| Fedora setroubleshoot | Fedora packages an AVC alert service and desktop client. The service turns records into alerts grouped by a problem signature, with behavior and visibility governed by its own configuration. [Fedora package](https://packages.fedoraproject.org/pkgs/setroubleshoot/setroubleshoot/) · [Fedora architecture notes](https://fedoraproject.org/wiki/Docs/Drafts/SELinux/SETroubleShoot/DeveloperFAQ) | Useful as a separate administrative tool. Its alert interface does not establish the completeness or per-record provenance expected by Lens. |
| Purpose-built reader | A system D-Bus service can authorize one operation using Polkit and disclose a bounded AVC-specific reply. The service introduces a privileged parsing, authorization and disclosure boundary. [Polkit action policy](https://polkit.pages.freedesktop.org/polkit/polkit.8.html) · [Polkit Authority API](https://www.freedesktop.org/software/polkit/docs/latest/eggdbus-interface-org.freedesktop.PolicyKit1.Authority.html) | Review this design before any privileged prototype. Prefer a maintained system interface if it provides equivalent scope, fidelity and authorization. |

On the Fedora 45 workstation, the desktop account could read AVC entries that journald received through the audit transport. Eight inspected entries had the trusted AVC type and transport fields but their messages did not include the audit epoch and serial. The journal remains a separate potential source with different provenance. Lens cannot use those entries as equivalent input for auditd record correlation.

## Caller identity findings and decision

On Fedora 45 in KVM, the unprivileged GNOME autostart process ran in `gnome-session-manager@gnome.service` below `user@1000.service`. The same UID had an active local Wayland login in `session-1.scope` on `seat0`. Both `GetSessionByPID` and `sd_pidfd_get_session` failed for the autostart process. This is consistent with GNOME launching work through a per-UID systemd user manager shared across logins. A pidfd prevents PID reuse from redirecting a lookup, but the process still needs an actual session association. [GNOME session management](https://gnome.pages.gitlab.gnome.org/gnome-session/re01.html) · [pam_systemd](https://www.freedesktop.org/software/systemd/man/latest/pam_systemd.html) · [systemd PID and pidfd lookup](https://www.freedesktop.org/software/systemd/man/latest/sd_pid_get_session.html)

Polkit 127 first attempts the process session and can fall back to the UID's display session. Its systemd session monitor can also derive active status from the user's aggregate state. In the guest, Polkit offered a challenge for the GNOME process with no direct logind association. A challenge expresses a potential authorization path. It provides no proof that this connection belongs to the active local session, and the probe did not establish why the subsequent interaction was rejected. [Polkit 127 session monitor](https://github.com/polkit-org/polkit/blob/127/src/polkitbackend/polkitbackendsessionmonitor-systemd.c) · [Polkit authorization results](https://polkit.pages.freedesktop.org/polkit/eggdbus-interface-org.freedesktop.PolicyKit1.Authority.html)

The console matrix reproduced the distinction with real same-UID sessions. Logind distinguished the active console, the inactive console and a PAM-marked remote login, while Polkit could offer a challenge to each. The prototype bound the active local console only. The guest's text-agent authentication confirmed legitimate administrator approval for a directly bound console session. This does not establish an eligible GNOME launcher path. [VM observations](FEDORA_VM_VALIDATION.md#observed-on-fedora-workstation-45-in-kvm)

| Approach | Trust and concurrent sessions | Maintenance and testability |
| --- | --- | --- |
| System-bus sender, UID and ProcessFD plus direct logind membership | Pins the connection's originating process and preserves per-session distinctions when logind can resolve them. The service must require the same logind owner and exact active local seat session throughout. An ordinary GNOME user service can lack a session relationship. A live connection also provides no per-message attestation after descriptors are shared. | Uses maintained kernel and daemon interfaces. The fail-closed GNOME outcome is reproducible. Keep these checks as the draft's minimum boundary. [D-Bus credentials](https://dbus.freedesktop.org/doc/dbus-specification.html) · [logind interface](https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.login1.html) |
| Verified Polkit bus-name subject | Suitable for the administrator decision after session binding. UID display fallback and user-level active state can conflate separate sessions. Runtime authorization rules can affect the decision, so the shipped action alone is insufficient evidence of a fresh prompt. | Maintained and compatible with GNOME authentication agents. Test denied, challenged, approved and dismissed requests independently of the session test. |
| Display-session lookup, user-manager membership, environment or client session ID | These identify a UID, a user service or an untrusted claim. A local and remote process under one UID can share a user manager. Kernel audit session numbers are inherited audit metadata and do not supply the required current seat attestation for a bus request. | Easy to implement but insufficient for this boundary. Keep them out of the eligibility decision. |
| Session-resident trusted consent provider | A maintained display-manager or compositor interface could attest the exact session and bind explicit consent to one connection, operation and lifetime. A per-UID socket, parent window handle or general relay would allow the wrong session to act as the requester. | Requires a documented authority and negative tests across concurrent sessions. The reviewed Fedora 45 interfaces provided no such audit snapshot endpoint. Window identifiers help place consent dialogs. [XDG portal security model](https://flatpak.github.io/xdg-desktop-portal/docs/security-model.html) · [Portal window identifiers](https://flatpak.github.io/xdg-desktop-portal/docs/window-identifiers.html) |
| Existing read-only tools and explicit administrator file handoff | The administrator independently queries a bounded interval with the existing audit tooling, reviews and deliberately releases a minimized snapshot. Lens would open an already-readable file and show file provenance and incomplete coverage. It would have no path from its UI to system audit files. Journal visibility and setroubleshoot alerts remain separate data sources with their own coverage. | Lowest privilege and maintenance burden for Fedora GNOME today. A future bounded importer can be tested without a daemon. The workflow depends on the authorized operator and file permissions, and still needs importer and disclosure review. |

Use deliberate administrator file handoff as the next architecture to evaluate. Keep direct desktop retrieval blocked pending a maintained session attestation mechanism and independent review. The current prototype continues to deny sessionless callers before Polkit or collection.

## Proposed version 1 contract

- Offer a separate user action for an authorized snapshot. Only this call sets the D-Bus flag that permits interactive authorization. Require the flag before starting a Polkit check. Starting the app, refreshing the direct source, and opening demo mode never invoke the helper. The only system bus method is `GetRecentAvcs()`, with an empty input signature and a versioned interface name. The service chooses the rolling ten-minute window and the auditd source. The client cannot provide paths, arguments, environment, filters, a caller identity, or a reply destination.
- Take the subject from the system bus message sender's unique name. Require the caller process descriptor and UID from the bus credentials. Check the descriptor is still live while resolving the caller's active local session and again before using that result. Use the unique bus name as Polkit's subject. Fail closed when a supported bus cannot supply the pinned identity. Allow one interactive administrator authentication for the explicit action, with `auth_admin` for active local sessions and `no` for inactive and remote sessions. Use no temporary grant. Fail closed on an unknown or vanished caller, missing authorization service, denial, or dismissed prompt. Check the caller is still connected and eligible before reading and before responding. Use a unique Polkit cancellation ID per request and call CancelCheckAuthorization on disconnect or deadline. Send records in the method reply only. [D-Bus credentials and interactive flag](https://dbus.freedesktop.org/doc/dbus-specification.html) · [Polkit cancellation](https://polkit.pages.freedesktop.org/polkit/eggdbus-interface-org.freedesktop.PolicyKit1.Authority.html)
- Keep the service and action files in administrator-owned package locations. Each request runs with a fixed executable and arguments, a minimal fixed environment, closed input, separate bounded stdout/stderr, and a kill-and-reap deadline. If using `ausearch`, use its raw output and system log mode. Verify the auditd configuration and log rotation paths used by the service are administrator-controlled. Require an enforcing SELinux confinement design that limits filesystem access to the required audit data and forbids policy or audit configuration writes. Prefer a dedicated service identity with narrowly scoped read access if supported without widening desktop permissions. Require evidence for these constraints before installation is proposed.
- Admit one request globally at a time so authentication and collection both have a bounded queue of zero. Rate-limit repeat prompts per caller UID and across callers, with bounded accounting and a timeout for pending authorization. Initial budgets for review are 60 seconds for authorization, 12 seconds for collection, 2 MB stdout, 16 KiB stderr, 16 KiB per input line, 200 records, and 256 KiB for the serialized reply. Set process-level CPU and memory limits and test them in the target Fedora environment. On timeout, cancellation, read failure, or an input cap, discard partial input and report the cause.
- Filter by the authoritative record type and audit identity before replying. Return typed, allowlisted fields for individual AVC/USER_AVC denials only, including the audit timestamp and serial, disposition, permissions, contexts, object class and explicit field availability. Do not pass through arbitrary raw text, command arguments, audit configuration, stdout or stderr. Enriched source fields and companion records need separate disclosure and provenance review. Indicate when a response hit a record or reply budget. Keep the auditd source, time window and coverage status explicit in the GUI.
- Use distinct outcomes for no records in a successful query, unobservable or unavailable source, unauthorized, cancelled, busy/rate-limited, capped, timed out and failed. Do not expose raw diagnostics in the UI or report. Any helper access log records only timestamp, UID, action and outcome, subject to the host's log retention settings. Records can still expose identities or system details even with a field allowlist.

## Installation and review

The current setup requires no helper or new access grant. A future implementation would be a separate opt-in signed Fedora package containing the root-owned executable, activation files, Polkit action and confinement. Its removal must remove the service and authorization entry and leave no persistent grants. Installation must preserve enforcing mode and existing audit configuration and access. No broad supplementary groups, relaxed log permissions or elevated GUI are part of this design.

A follow-up PR must demonstrate the boundary on an isolated Fedora GNOME VM with enforcing policy. Verify denial for ordinary unauthorized, inactive and remote clients, dismissed authentication, identity changes and disconnects during authorization, repeated prompts, missing infrastructure, direct malformed D-Bus calls and input with unexpected types. Verify bounded reads, rotated and unavailable logs, oversized results, hostile byte sequences, privacy of targeted replies and logs, deadline cleanup and an accurate empty state. Verify a successful authenticated request with synthetic test records, including permissive disposition and preserved provenance. Review installation, service identity, SELinux confinement and removal independently before enabling any privileged code.

## Uninstalled prototype

The prototype registers `GetRecentAvcs()` on a supplied D-Bus connection. Its reply contains a status and an array of tuples with audit epoch, serial, requested permissions, source context, target context, object class and disposition. Empty strings indicate unavailable text fields. Disposition 0 means unknown, 1 means enforcing and 2 means permissive. Raw audit lines, companion data, usernames derived from separate fields, command lines, paths and PIDs are excluded. Security contexts can still identify users or services.

The service pins the originating D-Bus process, logind's unique owner, and the exact session identity, timestamp and seat. It requires an active local user session on a seat, rechecks the same binding before authorization, before collection and before delivery, and cancels on relevant observed logind transitions. A loss of eligibility latches cancellation even if the same session becomes active again. Polkit receives the unique caller and the prototype rejects returned temporary and retained authorizations. The serialized D-Bus reply also has a byte limit. The prototype admits one request at a time and throttles attempts. An eligible caller awaiting authentication can temporarily occupy the request slot.

`make test-prototype` exercises the method on a private D-Bus with real peer credentials and simulated session, Polkit and audit responses. Separate tests in an enforcing KVM guest exercised real D-Bus, logind, Polkit and `ausearch` independently of the service. A GNOME autostart process had no matching logind session by PID even though Polkit offered a challenge. The reader fails closed on that path. Do not replace this check with UID-only lookup of an arbitrary desktop session or a client-provided session ID. [Reproducible VM probes and integration gates](FEDORA_VM_VALIDATION.md)

The draft has no activation unit, service identity, deployment policy or process-level CPU and memory limits. The stream and wire budgets cover application data. System-wide resource and SELinux confinement still need a reviewed candidate and end-to-end VM tests before application integration or deployment.

The pre-reply recheck and logind notifications reduce exposure to a session transition. They do not make the seat transition and D-Bus delivery one atomic operation. Independent review must assess notification ordering, peer descriptor ownership, authorization policy overrides and a hostile caller occupying the global request slot. Review these alongside the GNOME session-binding blocker.
